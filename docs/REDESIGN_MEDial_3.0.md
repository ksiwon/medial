# MEDial 3.0 — 연구 기반 리디자인 기획서

> 작성: 산업디자인 + UX 리서치 관점 설계 문서. 2026 최신 연구 근거에 정착.
> 범위: **기획(설계 사양) 단계**. 구현(R0–R6)은 이 문서를 기준으로 후속.
> 확정 전제: **데모 디바이스 = 스마트폰 / 태블릿**(반응형). 손목밴드는 IoT 데이터
> 소스로 *존재한다고 전제*(밴드 자체 UI는 본 범위 밖, 시뮬레이션 데이터로 대체).

---

## 0. 왜 다시 설계하는가 (문제 정의)

현 v2.x는 기능적으로 완결됐으나, 산업디자인 관점에서 **"화면"은 있으나 "프로덕트"가 없다**:
사용 맥락(디바이스·자세·시야·악력) 정의 부재, 어르신이 자기 데이터를 못 봄, 음성
인터랙션이 2-탭으로 부자연, 접근성(대비·타깃·전역확대) 미흡, 신뢰/존엄 장치 약함,
타입·컬러 토큰 비표준. 본 문서는 이를 **2026 연구 근거**로 재정의한다.

## 1. 설계 원칙 (Principle ← Evidence)

| # | 원칙 | 근거(2026 전후) |
|---|---|---|
| P1 | 제품은 *맥락 속 디바이스*다 — 거치 태블릿/손에 든 폰, 시야 30–50cm, 악력 저하 전제 | 웨어러블 착용 1순위 손목, 모니터링=이동성·낙상·부정맥·수면 (JMIR 2025, 109편) |
| P2 | 기능보다 **동기·신뢰**가 채택을 좌우 → "나에게 왜 좋은가" 우선 | 고령 웨어러블 수용: motivation > features (JMIR 2025) |
| P3 | 음성은 검증됨 — 단 **자연 턴테이킹(끼어들기·맞장구)** 설계 필수 | 55+의 90% "음성 쉽다"(MDPI 2025); LLM 음성에이전트 interruption/backchannel (CHI 2025) |
| P4 | **느린 발화 + 입모양**이 이해를 돕는다 (접근성 근거) | 음성속도 조절(PMC), 립무브먼트 효과(ScienceDirect 2024) |
| P5 | 신뢰는 **점진적 노출·데이터 투명성·지역 책임소재**에서 | Trust formation in healthcare AI, 고령자 (AIES 2025) |
| P6 | 모니터링은 '감시' 아닌 **'존엄·통제'** | Designing for dignity: AI surveillance in elder care (Frontiers 2025) |
| P7 | 접근성은 표준 + α — 타깃 ≥48px(>WCAG 24), 본문 17px+, 대비 AA | WCAG 2.2 SC 2.5.8 (W3C) + 노인 운동저하 가산 |
| P8 | 신뢰 채널 흡수 — 어르신이 보는 유튜브/마을 네트워크/건강TV | Formative Study(IRB-2026-56) DR1; KOCCA 숏폼 60대 54.3%/70대 40% |

## 2. 제품·사용 맥락 정의 (ID 핵심)

### 2.1 디바이스 구성
- **메디 허브 = 가정 거치형 태블릿**(주), **스마트폰**(보조, 외출 시). 반응형 단일 코드.
- **손목밴드(전제)**: 맥박·혈압·걸음·이동거리·수면·낙상 신호를 허브로 전송(현재 `signal_vital` 경로 재사용). 밴드 UI는 설계 범위 밖.
- 인터랙션은 **음성 우선 + 큰 터치 보조**. 키보드 입력 최소.

### 2.2 사용 맥락 가정 (치수 근거)
- 시야 거리: 태블릿 거치 **~50cm**, 폰 **~30cm** → 본문 17px+를 양쪽에서 가독.
- 자세/손: 앉아서, 한 손 또는 거치. **악력·정밀도 저하** → 터치 타깃 ≥48px, 간격 ≥8px.
- 환경: 농촌 가정 거실, 가변 조명 → **고대비** 필수, 다크모드/글래스 배제.
- 청력: 난청 가능 → 음성+**자막(말풍선)** 항상 병행, 음량/속도 조절.

### 2.3 퍼소나 & 하루 시나리오 (2.0 전용)
- 퍼소나: 김말순(73), 남해 독거, 고혈압약 복용, 유튜브 즐겨봄, 스마트폰 보유·문자 부담.
- 하루: 아침 안부(소통) → 식사 촬영 → 오후 밴드 혈압↑ 감지 → 메디가 *부드럽게* 상담 제안 → 동의 후 문진 → 보건소 전송 → "내 건강"에서 오늘 요약 확인 → 저녁 동네소식·건강영상.

## 3. 정보구조(IA) 재설계 — 3영역

```
하단 3탭 (큰 글씨·아이콘, ≥64px 높이)
┌──────────────┬──────────────┬──────────────┐
│   소통        │   내 건강      │   정보        │
│  (메디 대화)   │  (오늘의 나)   │  (소식·영상)   │
└──────────────┴──────────────┴──────────────┘
상시: 메디 아바타 · 글자크기(가–/가+) · 응급(119)
```

- **소통(Talk)**: companion↔triage 음성 대화. escalation·동의·전환멘트.
- **내 건강(My Health) [신규]**: 오늘의 걸음·혈압·수면·식사 **큰 카드**(어르신이 *자기 것을* 봄 = 존엄/통제, P6). 데이터 흐름·동의 토글. 식사 촬영 **큰 진입점**.
- **정보(Info)**: ①동네·보건소 소식(상단, 보건소 우선) ②건강 영상(하단, 큐레이션 탭-재생).

> 이유: 기존엔 어르신이 자기 바이탈을 못 봤고(우측 전시 패널에만 존재), 식사 촬영이 채팅에 묻혔다. '내 건강'으로 P2(동기)·P6(존엄) 동시 해결.

## 4. 인터랙션 모델

### 4.1 음성 턴테이킹 (P3, CHI 2025)
- **R1(즉시)**: 2-탭 → **누르고 말하기(push-to-talk)**. 떼면 자동 전송. 학습부담↓.
- **R2(목표)**: 서버 **VAD 자동 종료 + barge-in(끼어들기)** + 맞장구("네…", "그러셨군요") → 통화 같은 자연 대화.
- 지연 목표 **<2s**(실측 1.4s, thinking off). 듣는 중/생각 중/말하는 중 상태를 색+텍스트+모션 3중 표시.

### 4.2 음성 출력 (P4)
- TTS **속도(느리게 기본 0.85)·음량** 토글. 메디 **입모양 싱크**(Wav2Lip 실구현 또는 SVG 입 애니메이션 부활 — 현재 죽은 훅 정리).

### 4.3 온보딩 (DR1·P3)
- 최초 1회 **30초 가이드**("화면을 누르고 말씀만 하시면 돼요"). 이후 미표시, 필요 시 재호출.

## 5. 접근성 시스템 (P7, WCAG 2.2 +)

### 5.1 타입 스케일 (토큰화, 전 화면 통일)
| 토큰 | px | 용도 |
|---|---|---|
| caption | 15 | 메타·라벨(최소) |
| body | 17 | 기본 본문 |
| bodyLg | 19 | 대화 말풍선 |
| title | 24 | 섹션 |
| headline | 30 | 화면 제목 |
| display | 38 | 첫인사·핵심 |
- 줄간격 1.5–1.6, 단일 폰트(Pretendard), 자간 과대 금지.
- **전역 글자 확대** 1.0 / 1.15 / 1.3 (현재 채팅만 → 앱 전체), 단계 표시(보통·크게·더크게).

### 5.2 색 역할 (semantic, 전부 AA 4.5:1 검증)
| 역할 | 색 | 비고 |
|---|---|---|
| 평상/긍정 | sage 700 | 브랜드 |
| 정보 | healthBlue #1D5296 | 소식·영상 |
| 주의 | amber dark | 경계 신호 |
| 응급 | emergency red | 119 |
- **현 ink[300] 회색 보조텍스트 다수 AA 미달 추정 → ink[500]+로 상향**. placeholder·뱃지 포함 전수 점검.

### 5.3 터치/모션
- 모든 조작 타깃 **≥48×48px**, 간격 ≥8px(WCAG 24px 초과 — 노화 가산).
- `prefers-reduced-motion` 존중, 모션은 목적형(상태 전달)만.

## 6. 신뢰·존엄 레이어 (P5·P6)

- **데이터 흐름 카드**(내 건강): "맥박·혈압은 남해 보건소 OOO 선생님만 봐요. 음성은 저장하지 않아요." (지역 책임소재 명시 = AIES 신뢰요인; P10 보이스피싱 대응).
- **모니터링 동의 토글**: 어르신이 IoT/GPS 수집을 켜고 끔(감시 아닌 통제, Frontiers 2025).
- **설명가능 escalation**: 전환 시 *왜*를 부드럽게("어제보다 혈압이 높게 나와서요") + 상단 1회 배너.
- **상시 고지**: "참고용이에요, 진단은 보건소 선생님이 하세요." 응급은 항상 119 최우선.
- **점진적 노출**: 비위험 일상대화 → 위험 상담 (이미 옳은 구조, 강화).

---

## 7. 콘텐츠·보이스·톤

- 첫인사 **분리**: ①따뜻한 인사(음성) → ②개인정보/면책은 짧게 화면 고지(음성 과적재 방지).
- 의학용어 금지·공감1+질문1 유지. 소식 카드 "메디가 전해드려요"는 섹션 1회로.
- 영상: 가로형 큐레이션(끝없는 자동피드 배제), "오늘의 건강 영상" 라벨 유지.

---

## 8. 비주얼 시스템

- 타입/컬러/간격/터치 **토큰 단일 소스**(`styles/tokens.ts` 확장) → 전 화면 적용.
- '메디' 아바타 **정체성 통일**(원형 사진 1종, 상태 링). 홈 포스트카드도 동일 자산.
- 발표/전시 컷에서 **dev 패널(TweaksPanel) 숨김** 또는 접이식 분리.
- 세이지 단색 과잉 완화: 정보=blue, 주의=amber 포인트로 위계 부여.

## 9. 모드 단일화

- **2.0(동반+커뮤니티) = 유일한 제품.** Mock(단발문진)/Live는 "연구 진화 아카이브"로 격리(전시 별도 섹션) 또는 dev 전용.

## 10. 평가 설계 (CHI 제출 대비)

- **텔레메트리**: escalation 발생·정밀도(과/미탐), 상담 동의율, 식사기록률, 대화 길이, 재질문율(이해도 프록시).
- **연구 프로토콜**: 남해 고령자 사용성 세션(과업+발화사고) + 사후 반구조 인터뷰(신뢰·존엄 인지).
- **벤치마크**: 음성 지연, STT 오인식률, escalation confusion matrix.

## 11. 로드맵 (R0–R6)

| 단계 | 산출물 | 핵심 |
|---|---|---|
| **R0** | 디자인 시스템 토큰 + 디바이스/맥락 1장 | 타입·컬러·간격·터치 토큰, 퍼소나 |
| **R1** | 접근성 일괄 | 토큰 적용, 대비/타깃 보정, 전역 확대 |
| **R2** | IA 개편 | '내 건강' 탭, 식사 진입 승격, 데이터 흐름/동의 |
| **R3** | 음성 인터랙션 | push-to-talk→VAD, TTS 속도, 입모양 |
| **R4** | 신뢰·존엄·콘텐츠 | 첫인사 분리, 온보딩, 설명가능 escalation, 상시 고지 |
| **R5** | 비주얼 마감 + 모드 단일화 | 포인트 컬러, 아바타 통일, dev 패널 분리 |
| **R6** | 평가 텔레메트리 + 전시 안정화 | 로그, 데모 체크리스트 |

## 12. 리스크 · 열린 질문

- VAD/barge-in(R3-2)은 서버 STT 스트리밍 구조 변경 필요 — GPU 환경에서만 실검증 가능.
- 입모양 싱크: Wav2Lip(무거움) vs SVG 입 애니메이션(가벼움) 택1 필요.
- '내 건강' 데이터 정직성: 시뮬 데이터임을 전시에서 어떻게 고지할지.
- 모드 단일화 시 mock 케이스(연구 affinity 패널)의 거취.
