## 1. 당신의 역할

> 브라우저에서 열어 보고, 아래 순서대로 확인하고, **9장 형식 그대로 보고서를 써라.**

### 하지 말 것

- **코드를 고치지 마라.** 이상해 보여도 고치지 말고 **적어라.** 보고서를 받는 쪽이 고친다.
  (예외: 화면이 아예 안 떠서 검증 자체가 불가능한 경우. 그때는 **무엇을 왜 고쳤는지** 보고서
  맨 앞에 따로 적어라.)
- 문서를 다시 쓰지 마라. `DEVELOPMENT.md` · `17_NEXT_DESIGN_LLM_PROMPT.md` 는 그대로 둬라.
- 리팩터링·정리·이름 바꾸기 금지.
- 원자료(`local-data/`)·기존 session·기존 시도를 **삭제하지 마라.** 새로 만드는 것은 괜찮다.
- **스크린샷 외에 `fixtures/`에 아무것도 넣지 마라.** 실행 중인 서버는 실제 은점마을 데이터를
  서빙한다. 저장소에 원자료 파생 지명·나이·직업이 들어가면 안 된다.

### 토큰이 모자라면

1차는 토큰 소진으로 §5~§7을 통째로 못 했다. **이 순서로 해라. 앞의 것이 뒤의 것보다 중요하다:**

## 3. 배치 재확인 (수정 1·2번) — 최우선

**마을 관찰**을 열고 **1440×900**, **1366×768** 에서:

```js
[document.documentElement.scrollWidth, innerWidth]   // 같아야 한다
```

세 패널을 각각 DevTools로 클릭해 `getBoundingClientRect()` 를 읽고 **left와 width를 적어라.**
1차에서는 셋이 전부 `left 393 / width 1027` 로 같았다. **이제 left가 셋 다 달라야 하고 width가
셋 다 비슷해야 한다.** 셋이 또 같으면 수정이 안 통한 것이니 그대로 보고해라.

그다음 **1차에서 판정조차 못 했던 것**을 본다:

1. **3열(사람 패널)이 읽을 만한가.** 제목이 깨지거나, 표가 잘리거나, 문장이 한두 글자씩
   줄바꿈되지 않는가. → 그렇다면 **어느 섹션이** 그런지 이름을 적어라.
   (1차 스크린샷 기준 3열에는 이런 섹션들이 있다: 지금 / 오늘 일정 / 이 사람이 겪은 일 /
   주고받은 말 / 하루를 마친 뒤의 평가 / 원래 일과에서 벗어난 시간 / 페르소나.)
2. **지도 : '지금 일어난 일' = 1.6 : 1** 이 적절한가. 지도가 세로로 눌리지 않았는가.
   은점마을은 남북 1.15 km 세로 마을이라 **좌우 여백이 남는 것이 정상**이다 — 여백은 문제가
   아니고 **가로로 늘어난 것**이 문제다.
3. 세로 스크롤이 세 열에서 각각 따로 도는가, 페이지 전체가 밀리는가.

반응형:

- **1050px** (1279 미만): 지도 왼쪽 넓게 + 조율·사람 오른쪽 위아래. 1차에서 정상이었다.
- **860px** (899 미만): 한 열로 쌓임. **1차에서는 지도 트랙이 0px이라 조율 패널 위에 겹쳐
  그려졌다.** 이번엔 겹치지 않고 세로로 이어져야 한다. → 세 패널의 `top`과 `height`를 적어라.
- 1440 / 1366 / 1050 / 860 네 폭에서 `scrollWidth === innerWidth` 네 쌍을 적어라.

## 4. 팝오버 (수정 3번 재확인)

사람이 여럿 있는 지점을 **hover** 해서 카드를 띄우고 (**클릭해서 고정하지 말고**):

- **Escape로 닫히는가.** 1차에서는 hover로 연 카드가 Escape를 완전히 무시했다.
- 닫힌 뒤 포커스가 원래 마커로 돌아가는가 (`document.activeElement` 확인).
- **고정한 경우**(클릭)에도 Escape로 닫히는가.
- 포인터를 마커에서 카드로 옮기는 동안 닫히지 않는가 (1차 O).
- 동시에 하나만 열리는가 (1차 O).

1차에서 **못 본** 것:

- 지도 **네 모서리** 가까운 마커에서 팝오버가 잘리지 않고 뒤집히거나 밀려 들어오는가.
- **'더 알아보기'** 를 누르면 **3열이 그 사람으로 바뀌는가.** (새 모달이 뜨면 안 된다.)
- 차량이 움직이는 시각(재생 바를 이동 구간으로)에 차량 표식에 **탑승자가 표시되는가.**
  귀가 구간이 빈 차로 보이면 그 사건 번호를 적어라.
- 래스터 위에 **도로망이 두 겹으로** 그려지지 않는가. (도로는 지금 읽는 요청의 경로만.)

## 6. needs_decision 화면 (1차 미실시)

도달 설정은 확인돼 있다: 시나리오 deck **둘 다** · `maxGenerations = 2` ·
`maxCandidatesPerGeneration = 3` · 선택 규칙 `pareto_then_stop`.

실험 준비의 접힌 **실험 설정**에서 그렇게 맞추고 실행한 뒤 **결과 비교**를 열어라. 확인:

1. 갈라진 **대안 두 개**가 이익·비용·근거와 함께 **나란히** 보이는가.
   (여기서 "결정이 필요한데 고를 것이 없다"가 나오면 그것이 버그다 — 그대로 보고해라.)
2. **이유를 적기 전에는** '이 방향으로 계속'이 눌리지 않는가.
3. 어디에도 **'최고안' · '승자' · 자동 채택** 이 없는가.
4. 마지막 세대가 자동 우승자로 표시되지 않는가.

재현되지 않으면 **몇 번 시도했고 어떤 상태로 끝났는지**(`stalled`, `no_valid_change`,
`budget_exhausted` 등) 적어라. 실패도 보고 대상이다.

## 7. 오류 화면과 세션 중복 (1차 미실시)

세션 수는 API로 직접 센다. **콜드 스타트에서도 바로 200이어야 한다** (수정 6번):

```bash
curl -s http://127.0.0.1:8010/api/sim/iteration/sessions
```

- **create 실패**: 서버를 내린 채 '실험 시작' → "남은 것이 없다"는 취지의 화면이 뜨는가.
  흰 화면이나 콘솔 에러로 끝나면 안 된다.
- **start 실패 / 재시도**: start만 실패하는 상황에서 **'이 실험 실행 다시 시도'** 를 눌러
  **세션이 하나 더 생기지 않는지** 전/후 숫자로 확인해라.
- **'실험 시작' 3연타** → 세션이 1개만 느는가.
- **새로고침** → 세션이 늘지 않는가.

## 8. 흐름 한 바퀴 (1차 미실시)

설명 없이 이 순서를 밟을 수 있는지 직접 해 보고 **막힌 지점을 적어라**:
시작 → 관찰 → 리뷰 → 비교 → 현장 검토

- 하루가 끝나면 1열 아래가 '지금 일어난 일'에서 **주민 리뷰로 전환**되는가 (별도 화면 아님).
- 리뷰의 **'근거 장면 보기'** 를 누르면 그 시도가 열리고 **커서가 그 사건 번호로** 가는가.
  이때 **새 모델 호출이 생기면 안 된다** — 서버 로그에 호출이 찍히지 않는지 확인.
- 결과 비교에서 **현장 검토 시트**가 열리고, 선택이 **'서비스 도입 승인이 아니다'** 라고
  분명히 말하는가.
- 서버를 **재시작**한 뒤 새로고침하면 session · 버전 · **재생 커서**가 복원되는가.
  (1차에서 session·버전은 O, **커서는 확인 못 했다.** 커서를 중간으로 옮겨 놓고 재시작해라.)
- 1차가 남긴 것: 새로고침 직후 1~2초간 '실험 준비'가 먼저 그려졌다가 '마을 관찰'로 바뀐다.
  아직 그러는지 확인만 해라.
