# 08. 기존 프로젝트와 자료 점검

점검일: 2026-09-10. 읽은 파일의 주장과 실제 실행 검증을 구분한다.

## 1. coding/medial 현황

기존 프로젝트는 'AI 동반자 + 의료 커뮤니티'를 지향하는 React/Vite 프론트와 FastAPI 음성·트리아지 서버다. 지금 만들 연구자용 마을 시뮬레이터와 제품 목적이 다르다.

읽은 파일: package.json, README.md, server/requirements.txt, server/app/modules/orchestrator.py 일부, src/hooks/useWebSocket.ts 일부, .gitignore, 소스 경로 목록.
기존 서버·음성·외부 모델을 실행하거나 성능을 다시 검증하지 않았다. README의 과거 검증 완료 주장은 이번 검증 결과가 아니다.

발견한 미커밋 변경:
- src/components/companion/CompanionOnboarding.tsx
- src/store/useAppStore.ts

두 파일과 기존 코드는 이번 작업에서 수정/삭제하지 않았다. 사용자가 정리를 허용했지만, 당장 새 설계 문서를 만들기 위해 데이터·코드를 지울 필요가 없고 변경 내용을 잃을 이유도 없다.

## 2. 재사용 판단

| 대상 | 판단 | 이유 |
|---|---|---|
| React/Vite/TypeScript 앱 골격 | 재사용 | 연구 UI를 별도 feature로 만들 수 있음 |
| 스타일 토큰·폰트·일부 아이콘 | 선택 재사용 | 연구 화면 시각 체계에 맞게 적용 가능 |
| HTTP/WS 통신 패턴 | 참고 | 기존 메시지는 음성 세션 중심이므로 event log 프로토콜은 새로 필요 |
| 기존 Zustand app store | 직접 확장하지 않음 | 말동무·음성·triage 상태와 simulation truth가 섞임 |
| companion 화면·가상 의사 | 새 연구 화면에서 사용하지 않음 | 설계 도구의 목적과 다름 |
| STT/TTS/avatar/GPU 파이프라인 | 후순위 보관 | 첫 단계는 텍스트와 사건 조율의 타당성 |
| PubMed/FAISS/DDXPlus | 신규 simulation 경로에서 사용하지 않음 | MEDial의 조율 설계와 진단 생성은 다른 문제 |
| 기존 clinical escalation | 채택하지 않음 | 이 목적에 검증된 기준 아님; 상태 분류와 임상 지침을 혼합할 위험 |
| 원본 지도·ROUTES·HOME·PLACE | 원출처에서 추출 | 이미 사용자 검토를 거친 지리 기반 |
| 현재 HTML의 UI 상호작용 | 동작 명세로 재사용 | P번호·그룹 팝업·밖 주민·좌우 분할·시도 비교 |
| 현재 HTML의 고정 대화/별점 | 엔진 근거로 재사용하지 않음 | UI 데모 값이며 실제 사람/모델 실행 결과가 아님 |

기존 orchestrator.py에는 '누적 suggest=2'를 임상 척도와 연결하는 설명이 있다. 이를 그대로 새 엔진에 옮기지 않는다. 척도의 cutoff를 대화 사건 개수에 대응시키는 것은 별도 타당화 없이는 성립하지 않는다. 의료 판단 로직의 전체 검토를 한 것은 아니다.

## 3. 연구 자료의 근거 우선순위

현재 사용자 요구 → 확인된 원자료/전사 → 페르소나 JSON·원본 시뮬레이터 → 과거 연구 기획/요약 문서.
단, JSON과 시뮬레이터도 편집된 연구 자료이며 실제 측정 그 자체는 아니다. 충돌 시 숨기지 않고 data issue로 기록한다.

확인한 충돌:
1. 연구_파이프라인.md에는 12명 인터뷰 완료 표현이 있으나 JSON은 P12 인터뷰 없음.
2. gap_주장구조.md는 '전수'라 쓰지만 평가 기획안은 참여자 12명 외 마을 주민 미반영을 명시.
3. 익명 JSON도 가명 인명·관계·사례를 담는다. 화면 ID 정규화와 공개용 익명성 검토는 별도 작업.
4. P3/P9/P12의 plan에는 퀘스트 수행 결과가 들어 있다. baseline으로 무비판적으로 쓰면 정책 비교가 성립하지 않음.
5. 관계 모임 정보는 양방향 부탁 가능성·수락 확률과 같지 않음.
6. 지도 거리/소요시간/기관 출동시간은 측정·추정·원본 데모 값으로 구분 필요.
7. 소장·방문 담당자·119 상황실·구급대의 실제 업무 자료가 페르소나에 없음. role templates와 가정을 먼저 쓰고 기관 인터뷰로 보완.
8. source replay의 Q3는 무응답에 대한 안부 확인 결과다. experiment에서는 불필요한 확인 요청 자체가 다른 정책에서 발생하지 않을 수 있음. 모든 정책에 Q3 방문을 강제로 넣지 않음.
