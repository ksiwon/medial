## 제품 목적
완성된 의료 아이템의 점수를 매기는 검증기가 아니다. 연구자가 core item을 설정하고 정책 조건을 바꿔 여러 attempt를 실행한 뒤, 결정 과정·주민 경험·업무 부담을 비교해 아이템을 구체화하는 도구다. AI Orchestrator 이름은 MEDial이다.
기존 companion/음성/가상 의사 앱과 신규 simulation 도메인을 분리하라. React/TypeScript/Vite 골격은 활용하되 이전 triage·RAG·GPU 경로를 새 기능에 연결하지 마라.

## 첫 구현 범위
1. 원자료 importer와 근거/가정 구분. P3/P9/P12 원본 일과에는 픽업·동승 같은 기존 퀘스트 결과가 포함돼 있으므로 source replay와 실험 baseline을 분리하라. 판단 불가능한 기본 일과는 가정으로 명시하고 원본을 덮어쓰지 마라.
2. Python/FastAPI/Pydantic 기반 사건 엔진과 SQLite 로그. 시뮬레이션 시간, 순서가 고정된 사건 큐, 관측 필터, 정책 revision, attempt, 결정 기록을 구현하라.
3. P1 09:30 미응답 시나리오 하나를 끝까지 연결하라. 시간·기관 가용성은 실험 가정이다. 미응답만으로 응급상황을 확정하지 마라.
4. 정책 A(이장 우선 확인)와 B(재연락 후 보건소 담당자 전달)를 같은 외생 사건과 초기 상태로 비교하라. 달라지는 실제 연락·대기·업무와 후속 사건이 로그·지도·비교 화면에 함께 반영돼야 한다.
5. API 키 없이 Scripted/Rule adapter로 동작하게 하라. LLM adapter는 교체 가능한 인터페이스부터 만들고 모델 호출 없이 테스트 가능하게 하라.
6. 재생·일시정지·한 단계·로그 재생·새 시도·조건 차이/결과 비교를 연결하라. 저장된 로그 재생에서 모델을 다시 호출하지 마라.

## 지켜야 할 모델 규칙
- 엔진의 실제 세계 상태, 각 행위자가 아는 정보, 연구 근거를 분리하라. MEDial에게 미래 사건·사적 기억·미관측 건강 상태를 주지 마라.
- 에이전트는 ActionProposal만 제출하고 검증된 DomainEvent만 상태를 바꾸게 하라.
- 기본 일과, 개입으로 수정한 계획, 실제 수행 이력을 분리하라. 거절해도 예정된 픽업이 일어나는 모순을 막아라.
- 주민별 근거 카드/기억/관측을 분리하라. 없는 특성·수락 확률은 사실처럼 만들지 마라. P12 인터뷰 부재, P10/P11 공동 인터뷰의 한계를 남겨라.
- 주민은 거절·조건부 수락·연락 연기·정보 비공개가 가능하다. 거절을 자동으로 신뢰 하락으로 계산하지 마라.
- 이장은 P6와 동일 행위자이며 시간 예산도 하나다. 보건소장·실무자·119 상황실·구급대는 역할과 자원이 다르다.
- 첫 범위 이후 차량 좌석·시간 중복·귀가·도로/해상 경로 제약을 확장하라. 실제 기관 연락이나 출동 기능은 만들지 마라.
- 모델 장애를 주민 거절/무응답으로 기록하지 마라.
- 계약 JSON은 최소 초안이다. 구현 시 Pydantic을 계약의 단일 원천으로 만들고 사건별 payload·참조·권한을 엄격하게 검증하라. 자리표시자 예제를 실행 완료 fixture로 취급하지 마라.

## UI 요구
실제 은점마을 지도에 맞춘 평면 2D 지도다. 3D·기울기·가상 도시를 다시 만들지 마라. 북쪽을 위로 맞추고 지도는 왼쪽, MEDial 상태/퀘스트 과정은 오른쪽 상단, 대화·이슈·안내는 오른쪽 하단에 둬라.
주민 표기는 P1~P12, P6는 이장이다. 작은 얼굴과 작은 상태 아이콘을 쓰고 차량은 분명하게 보여라. 함께 있는 주민은 묶고 공통 컴팩트 팝오버에서 사람을 선택하게 하라. 팝오버에는 현재 활동과 작은 더 알아보기 버튼을 둬라. 지도 밖 주민은 별도 목록으로 보여라.
각 주민 상세에는 일과·대화·이용 기록·하루 종료 모의 피드백을 연결하라. 첫 구현에서 지원하지 않은 항목은 구현된 것처럼 표시하지 마라.
연구자의 읽기 전용 대화는 상태를 바꾸지 않고, 개입 대화는 새 branch로 기록하라. 장식적인 자잘한 설명과 고정 만족도 별점을 제거하라.

## 비교와 평가
실제 발생한 대기/완료/연락/업무 부담, 에이전트의 모의 피드백, 실제 사람 평가를 구분하라. 피드백은 경험한 사건에 연결하고 근거가 없으면 unknown으로 남겨라. 연구자에게 조건 차이→결정 차이→결과 차이를 보여라. 합성 피드백을 실제 주민 만족도나 임상 효과라고 부르지 마라.
정책 수정은 새 revision이다. 실행 중 수정은 새 attempt branch다. 동일 seed가 동일 LLM 결과를 보장한다고 주장하지 마라.
