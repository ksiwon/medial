# 03. MEDial·이장·보건소·119 역할과 발전 경로

역할표는 연구용 모델의 제안이다. 공식 안내에서 확인한 기관 역할과, 실제 기관 협의가 필요한 운영 가정은 구분한다. 실제 의료·기관 API 연동은 초기 범위에 없다.

## 1. 누가 무엇을 결정하는가

| 행위자 | 아는 것 | 할 수 있는 일 | 결정하지 못하는 일 |
|---|---|---|---|
| 주민 P1~P12 | 자기 상태·일과, 직접 받은 메시지·경험 | 필요 표현, 수락·거절·조건 제시, 채널·공개 범위 선택 | 다른 주민의 비공개 상태 열람 |
| 이장=P6 | 자신의 관계 지식·직접 관찰·전달받은 상황 | 주민에게 확인, 지역 안내, 자원 소개, 조율 제안·이의제기 | 전 주민 건강정보 자동 열람, 본인 동의 대신 결정 |
| MEDial | 동의된 프로필, 전달받은 관측, 공개/허용 일정, 담당자가 공개한 자원 | 다음 행동 제안, 조건 확인, 동의 요청, 예약 요청, 전달·재확인 | 숨겨진 필요 열람, 수락 강제, 임의 임상 판단·기관 출동 확정 |
| 보건소장 HC_DIRECTOR | 업무량 요약·미해결 요청·허용된 사례 | 운영 우선순위·담당 범위·인력 배치 규칙 설정, 예외 검토 | 모든 진료를 직접 수행한다고 가정하지 않음 |
| 보건소 담당자 HC_NURSE | 배정된 사례·동의된 건강정보·근무표 | 상담/방문 접수 검토, 시간 확인, 후속 연락, 전문직 의뢰 | 무한한 방문 처리, 면허·업무 범위를 넘어선 처방 |
| 119 상황실 EMS_DISPATCH | 신고 내용·위치·제공된 환자정보·출동 자원 | 신고 접수, 필요 정보 확인, 출동/안내/병원 연계 절차 | MEDial의 추천을 실제 출동 확인으로 간주하지 않음 |
| 구급대 EMS_CREW | 출동 지시·현장 정보·위치·환자 인계 내용 | 이동, 도착, 현장 평가/처치, 이송·병원 인계 이벤트 | 도착만으로 환자 문제 해결/생존 성공 처리 |
| 약국·병원 SERVICE_* | 해당 의뢰와 필요한 정보·업무시간 | 상담/예약/수령 확인·회신 (초기에는 스크립트) | 모든 질문에 즉시 응답 |
| 연구자 | 출처와 전체 시뮬레이션 | 사건 편집·분기·관찰·정정·정책 채택 | 개입 흔적 없이 결과 조작 |

주민 12명 + MEDial 1 + 기관 역할 4 = 논리적 행위자 17개부터 시작한다. 기관 역할은 처음부터 LLM일 필요가 없다. P6는 주민과 이장 역할이 함께 있는 한 사람이며 별도의 두 시간 예산을 주지 않는다.

## 2. 보건소를 구체적으로 어떻게 넣을 것인가

남해군 공식 안내는 방문건강관리를 보건소의 간호사·물리치료사 등 전문인력이 제공하는 서비스로 설명한다. 대상자 신청·등록·서비스 지원 절차가 있다. 따라서 소장 한 명이 모든 건강 요청에 즉시 답하는 구조는 적절하지 않다. [남해군 방문건강관리 안내](https://www.namhae.go.kr/modules/welfare/info/info.do?amode=view&pageCd=DE0101000000&siteGubun=depart&sno=152)

### 두 개의 화면과 업무

소장 화면:
- 오늘 접수량보다 미처리 이유·처리 기한·담당자 업무량·장기 미접촉 대상을 먼저 봄.
- “오후 방문은 담당자 1인, 비응급은 동의된 시간대로 묶기”와 같은 운영 조건을 설계함.
- 개별 요청의 증상 전문 대신 필요한 범위의 요약으로 접근.
- MEDial이 제안한 방문 묶음이나 이장 경유 규칙을 채택/수정/보류.
- 소장의 지시 역시 버전과 출처가 있는 이벤트로 보존.

담당자 화면:
- 접수 검토 → 동의·연락 확인 → 방문/상담 가능 시간 → 서비스 예약 → 수행 기록 → 후속 확인.
- 연락 실패, 잘못된 주소, 중복 의뢰, 담당자 부재, 자격 확인 대기를 독립 상태로 가짐.
- 현장 검토의 시간도 자원 점유로 계산; “보건소에 넘김”으로 MEDial의 일을 종결하지 않음.

초기 자원 가정 예: 연구용 담당자 1명, 근무 09:00–18:00, 점심·기존 예약 제외, 상담 10/20분·방문 20/40분의 민감도 조건. 이는 남해군 실제 인원·소요시간 통계가 아니다. 운영시간 일부가 공식 안내와 같아도 capacity는 별도로 확인해야 한다.

기관 좌표가 없는 동안 지도 밖 '연계 기관' 노드로 표시한다. 측정되지 않은 지점과 이동 시간을 실제처럼 만들지 않는다.

## 3. 119를 단일 캐릭터로 두지 않는다

소방청 안내에서 확인되는 신고·응급처치 지도·이송병원 연계 기능과 현장 구급대 역할을 구분한다. [소방청 119구급과](https://www.nfa.go.kr/nfa/introduce/organizationidfo/firstaid/), [구급차 도착 전 준비](https://nfsa.go.kr/nfa/safetyinfo/emergencyservice/emergencydeclarationbefore%3Bjsessionid%3DNL3bLvCO6e%2BIiwUK8wvxpXGy.nfa22)

연구용 과정:
신고 필요 관측 → 신고/연락 시도 → 상황실 접수 확인 → 자원 배정 → 출동 → 도착 → 현장 담당자 인계 → 이송 → 병원 인계.

- MEDial은 접수 확인을 받기 전 '출동 중'이라고 표시하지 않는다.
- 보건소장·이장의 응답이나 승인 대기 때문에 응급 연락을 보류하지 않는 것을 초기 불변 규칙으로 둔다.
- 이웃의 역할은 위치 안내, 현장 정보 전달, 상황실 안내를 받을 연결 유지 등으로 정의한다. 전문 응급처치를 독자적으로 지시하는 LLM을 만들지 않는다.
- 증상·처치 판단을 공부시킨 자동 의사 대신, 전문가가 검토한 사건 단계와 의료지도 메시지 템플릿을 사용한다.
- 약물·병력·변화 시점은 알려진 값만 넘긴다. 미확인 정보는 unknown, 정보 시각·신고자·수정 이력을 함께 전달.
- 구급대의 실제 자격별 처치 범위, 거절 처리, 이송 결정 세칙은 기관 검토 전 확정하지 않는다.
- 기존 AMB.call=1234, arrive=1256은 20:34→20:56, 원본 데모의 22분이다. 실제 남해 119 평균 출동시간으로 해석하지 않는다.
- 119 안심콜은 사전 등록 정보를 신고 시 활용하는 실제 서비스다. 최소 인계 패킷 설계의 참고점으로만 사용한다. MEDial이 접근 가능한 API나 등록 권한을 확보한 것은 아니다. [소방청 안심콜](https://www.nfa.go.kr/nfa/safetyinfo/emergencyservice%3Bjsessionid%3DexOkbrUu0tywuLCJIRhXdgUi.nfa21)

응급 사례의 측정은 요청→접수, 접수→배정, 배정→도착, 인계 누락, 연락 실패, 역할 이탈이다. 생존율·진단 정확도는 이 시뮬레이션의 결과 변수에서 제외한다.

## 4. 이장의 입장

P6는 MEDial의 하위 실행자가 아니다. 지역 조율을 이미 하는 사람이며 시스템의 도입·수정에 의견을 가진 이해관계자다.

- 지역 지식: 직접 아는 이동 제약·연락처·최근 만남을 제공. 확인 시각이 지나면 최신 사실로 취급하지 않음.
- 정당성: “내 이름으로 부탁하지 말라”, “직접 연락 전 먼저 소개하자”는 운영 선호를 표현할 수 있음.
- 개인 생활: 순찰·식사·자기 일이 있으며 보건소보다 항상 먼저 이용 가능한 무료 노동력이 아님.
- 협업: MEDial의 후보·제외 이유를 보고 수정 제안. 수동 개입도 평가 가능한 사건.
- 결과: 업무를 줄였는가만 보지 않고, 이전에 닿지 않던 필요가 처리되었는지, 기록/설명 업무가 얼마나 생겼는지도 본다.

이장 중심, 이장에게 제안하는 MEDial, 동의된 주민 직접 연결의 세 정책을 비교하되 '직접 연결이 더 진보적'이라는 선결론은 두지 않는다.

## 5. MEDial의 실행 그래프

    observe
      → classify_coordination_need
      → check_urgency_path
      → request_missing_information
      → filter_eligible_resources
      → propose_contact_and_disclosure
      → get_resident_and_provider_response
      → reserve
      → monitor_execution
      → confirm_service_or_handoff
      → follow_up

분기 상태: no_response, declined, conditional_acceptance, deferred, waiting_professional, waiting_resource, withdrawn, cancelled, unresolved, completed.

- 모든 후보에게 거절할 실제 행동 선택지를 제공한다.
- 정보 공개의 대상·내용은 연락 전 확인한다.
- 거리·차량·근무표·예약 중복은 코드가 계산한다.
- MEDial의 LLM은 허용 후보 안에서 제안하고 간단한 이유와 근거 ID를 낸다.
- 이유는 검토 가능한 decision summary이며 내부 사고과정의 전문을 수집하려는 기능이 아니다.
- 자원 부족이거나 이유가 불충분하면 기다리기·기관 문의·추가 확인을 정당한 결과로 둔다.

## 6. 어떻게 발전시키고 확인할 것인가

| 단계 | 바꾸는 것 | 확인할 것 |
|---|---|---|
| M0 원본 재생 | 없음 | UI/입력 추출 정확성. 효과 비교 정책으로 사용하지 않음 |
| M1 규칙 기준선 | 확인된 연락망·시간·자원 규칙 | 사건→행동→실제 일정이 일치하는지 |
| M2 제약형 MEDial | LLM이 허용 행동에서 제안·질문·설명 | M1보다 어떤 설계 가능성을 열며 어떤 오류를 만드는지 |
| M3 개인 조건 | 연락 채널·시간·공개 선호를 명시적 변경 | 각 주민의 선호와 근거에 맞고 타인에게 비용을 떠넘기지 않는지 |
| M4 기관 공동 조율 | 소장·담당자·상황실·출동대 상태 연결 | 인계 누락·대기·책임 경계가 줄어드는지 |
| M5 정책 수정 보조 | 관찰에서 policy patch 초안 생성 | 새 사건에 일반화하고 연구자가 변경 이유를 이해하는지 |

M5는 자동 자기학습/자가배포가 아니다. 문제 장면 + evidence IDs + 바꿀 필드 + 기대 효과 + 예상 손실 + 새 확인 사례를 제안하고, 연구자가 적용한 새 revision에서 실행한다. 모델 fine-tuning·강화학습은 충분한 검토 데이터가 쌓이기 전 후순위다.

초기 정책에서 열어둘 변수:
- proactive check-in 유무와 대상 선정
- quiet window, repeat budget, channel preference
- leader mediation mode
- helper contact cap와 assistance minute cap (서로 다른 제약)
- request bundling과 양방향 이동 분리
- least-disclosure rule, subject consent
- health-center review capacity와 handoff timeout
- uncertainty가 클 때 추가 질문/기관 인계 조건

임상적으로 긴급한 사건의 응급 연락 경로는 일반 연락 횟수 상한에 막히지 않게 따로 분기한다.
