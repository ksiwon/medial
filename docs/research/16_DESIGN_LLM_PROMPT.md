# 수정용 LLM 실행 프롬프트

작업 폴더: C:\Users\pjo12\Downloads\coding\medial

사용자는 현재 UI를 거부했다. 기능은 있어도 버튼과 탭이 너무 많아 무엇을 해야 할지 알 수 없고, 지도 디자인도 연구용 도구로 만족스럽지 않다. 이번에는 기능 추가보다 정보 구조·지도·시각 디자인을 실제로 다시 구현하라.

먼저 AGENTS.md와 DEVELOPMENT.md, docs/research/12_FINAL_RESEARCH_PLAN.md, 13_ITERATION_IMPLEMENTATION_SPEC.md를 읽고, **15_DESIGN_RESET_SPEC.md 전체를 화면 구현의 구체 기준으로 적용하라.** 이전 문서의 6~7개 연구 단계는 세 화면으로 통합한다. 데이터 계약과 연구 역할 구분은 유지한다.

핵심 결과:
1. 최상위는 실험 준비 / 마을 관찰 / 결과 비교 세 개만.
2. 준비는 질문·초기안·접힌 설정·실험 시작. 세션 생성과 실행을 버튼 하나로 연결하되 실패/중복을 정확히 처리.
3. 관찰은 실제 북쪽 위2D 지도 왼쪽, 현재 MEDial 요청 흐름 오른쪽 위, 사건·대화·하루 리뷰 오른쪽 아래.
4. 작은 얼굴, 확실한 차량, 한 집단당 하나의 컴팩트 팝오버, 마을 밖 별도 목록. 지형을 늘리거나 가상의 도시를 만들지 말 것.
5. 결과는 조건 변경 → 주민 경험/리뷰 → 개선 → 결과 차이를 읽고 현장에서 검토할 안을 고르는 곳. 리뷰/개선/현장 검토를 각기 최상위 버튼으로 두지 말 것.
6. 내부 해시·JSON 경로·미구현 목록·모든 실험 버튼은 기본 화면 밖의 필요한 상세로 이동. 오류와 실행 방식 구분은 유지.

이전 세션이 직접 수정한 IterationSetup.tsx의 접힌 설정·타이포와 SimulationApp.tsx의 수동 도구 분리는 임시 정리다. build는 통과했지만 시각 검증은 하지 못했다. 이를 최종 디자인으로 답습하지 말고 명세의 완성된 흐름으로 교체하라.

실행 순서:
- 현재 서버/프런트 상태와 실제 화면을 먼저 확인하고, 가능하면 수정 전 스크린샷을 저장.
- 명세8장의6개 작업 단위로 실제 코드를 수정. 사용자에게 이미 정해진 디자인을 다시 선택하라고 묻지 말 것.
- 연구 단계와 UI 화면을 분리하고, 기존 세션 복원·수동 비교·근거 탐색을 유지.
- 지도 투영/배치와 작업별 MEDial 요약을 브라우저에서 확인.
- 의미 있는 흐름 검사와 build를 실행.
- 명세9장의A~D 스크린샷으로 실제 결과 확인. 과밀하면 직접 다시 줄여라.
- DEVELOPMENT.md를 실제 구현 상태로 갱신하고 변경/검증/남은 제한을 보고.

금지:
엔진 전면 재작성, 원자료/사용자 수정/기존 세션 삭제, 관측 불가능한 정보 유출, 가짜 만족도·대화·응급출동, 원래 없던 LLM 능력 표시, 거대한 카드·9px 설명·늘어선 버튼으로 화면을 다시 채우기, 기존 큰 패널들을 새 탭 안으로 통째로 옮긴 뒤 완료 선언.

완료 기준은 버튼 수가 줄어든 스크린샷만이 아니다. 설명 없이 시작→관찰→주민 리뷰 확인→버전 비교→현장 질문으로 갈 수 있어야 한다. 재생과 루프 실행은 구별되어야 한다. 시각 검증을 못했으면 디자인 검증 완료라고 쓰지 말 것.
