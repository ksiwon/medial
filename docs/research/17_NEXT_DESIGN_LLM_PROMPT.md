## 3. 반드시 유지해야 하는 규칙

전부 **실제로 잘못 나왔던 것**을 고친 결과다. 리팩터링하다 되돌리기 쉬우니 이름을 기억해라.

1. **`world.*` 사건은 요청 흐름에 들어가지 않는다.** `world.reachability_resolved`는 요청의
   correlation id를 갖지만 무응답의 *세계 쪽 이유*이고 연구자 전용이다. 이게 흐름에 들어가서
   MEDial의 상태 문장에 노출됐다. `requestFlows`의 `startsWith('world.')` 제외를 지우지 마라.
2. **`knownFacts`는 `medial.decided` payload가 아니라 DecisionRecord에 있다.** payload에서
   읽으면 항상 빈 배열이고 "MEDial이 알고 있던 것 0가지"가 된다. `decisionId`로 잇는다.
3. **`currentSentence`에 raw type fallback을 다시 넣지 마라.** 모르는 사건은 "아직 문장으로
   표시하지 못합니다"라고 말한다. 내부 타입 이름은 상태가 아니다.
4. **집단 묶음(사회적 사실)과 겹침 회피(그림)를 다시 합치지 마라.** `clusterPoses`는 장소·차량,
   `spreadOverlaps`는 픽셀. 같은 좌표에 사는 P10·P11은 **두 표식**으로 남아야 한다.
5. **래스터가 있을 때 도로 폴리라인 전체를 다시 그리지 마라.** 원자료 래스터는 OSM 파생이고
   도로와 길 이름을 이미 담고 있다. 도로는 읽고 있는 요청의 경로만.
6. **`callBudget = 0 은 무제한`이라는 서버 계약을 몰래 바꾸지 마라.** 준비 화면은 규칙
   어댑터일 때 0을 두고, LLM을 켜는 순간 1 이상을 요구한다.
7. **불러오기는 실행하지 않는다.** `store.bootstrap`이 정책을 실행하게 되돌리면 새 브라우저로
   열기만 해도 시도가 생긴다. `test_reading_a_session_never_starts_one`이 지킨다.
8. **기록 재생과 루프 실행은 다른 컨트롤이다.** 지도 아래 재생 바 vs 진행 표시의 실행 제어.
9. **needs_decision의 후보는 부모 세대에 있다.** 오른쪽 열에서 읽으면 항상 비어 있어서
   "결정이 필요한데 고를 것이 없는" 화면이 된다. `decisionPoint`를 session 전체에서 찾는다.
10. **사람 이름과 조사는 `story.personName` / `story.withParticle` 하나로만 만든다.** 패널마다
    `=== 'P6' ? '이장'` 을 따로 두면 같은 사람이 패널마다 다르게 불린다.
11. **3열에 만족도 점수를 만들지 마라.** 리뷰는 차원별 평가를 내놓고, 평균 내면 실행이 측정한
    적 없는 숫자가 생긴다. **자유 대화도 만들지 마라** — 로그의 utterance만 인용한다.
12. **`fixtures/ui/`는 합성 마을에서만 생성한다.** `scripts/gen_ui_fixtures.py`. 실행 중인
    서버에서 curl로 받으면 원자료 파생 지명·나이·직업이 저장소에 들어온다.
13. **마을 관찰의 세 열은 area 이름으로 자리를 잡는다.** 열을 정의하는 **모든 폭**이
    `grid-template-areas` 를 함께 선언해야 한다. 하나라도 빠지면 그 이름이 line name으로
    해석돼 **세 패널이 같은 셀에 겹쳐 그려진다** — 실제로 1280px 이상에서 그렇게 나갔고,
    mount 검사는 세 열이 문서에 다 있으므로 전부 통과했다. `screens/layout.test.ts` 가 지킨다.
14. **지도 프레임 안의 버튼은 `data-overlay` 를 달아야 한다.** 프레임은 pan을 위해
    `setPointerCapture` 를 걸고, 포인터가 잡히면 뒤따르는 click이 프레임으로 재타깃된다.
    이것 때문에 팝오버의 '더 알아보기'와 확대/축소가 **클릭 자체가 발생하지 않았다.**
15. **팝오버 Escape는 함수형 상태 갱신이어야 한다.** 포커스를 마커로 되돌리면 focus 핸들러가
    같은 배치 안에서 실행되고, 값을 그대로 읽으면 방금 만든 닫힘을 스스로 되돌린다.
16. **내부 코드를 문장에 넣지 마라.** 사유는 `story.reasonText` / `reviewers.reason_ko`,
    평가는 `ASSESSMENT_LABELS`, 장소는 `positions.placeLabel` 하나씩만 쓴다. 코드는 사건
    payload에 그대로 두고 — 지표와 필터가 그것을 쓴다 — 화면 문장에만 넣지 않는다.
17. **`describe()` 는 서버의 거절을 고쳐 쓰지 않는다.** 400/409의 한국어 detail은 어떤
    조건이 거절됐는지 말하는 유일한 문장이다. 걸러내는 것은 전송 실패의 상투구뿐이다.
18. **`docs/research/screenshots/` 는 저장소에 넣지 않는다.** 실서버 스크린샷에 주민의
    일과·장소가 담긴다. `local-data/` 를 제외하는 이유와 같다.
19. **쌓인 배치에서 지도 열의 `min-height: 0` 을 되살리지 마라.** 다른 두 열이 요구하는
    최소 높이가 뷰포트를 넘으면 지도 트랙이 0px을 받고, 자식은 제 크기로 그려져 조율 패널
    위에 겹쳐 칠해진다.

## 4. 남은 작업

### A. 브라우저 시각 검증과 A~D 스크린샷 (가장 중요, 반드시 먼저)

> **2026-09-11 갱신:** 1차 브라우저 검증을 수행했고 **1:1:1 배치가 겹쳐 있는 것을 발견해
> 고쳤다.** 아래 원문은 1차 이전에 쓴 것이다. **지금 유효한 지시서는
> `docs/research/18_BROWSER_VERIFY_PROMPT.md`(2차)** 이고, 1차 결과와 남은 항목은
> `DEVELOPMENT.md` 의 '브라우저 검증 1차' 절과 '아직 브라우저에서 보지 못한 것'에 있다.

**직전 세션은 1:1:1 배치를 브라우저에서 보지 못했다.** 세션 중간에 브라우저 도구 연결이
끊겼고, 그 이후 작업은 mount 검사(jsdom)로만 확인했다. jsdom은 레이아웃을 계산하지 않으므로
**세 열이 실제로 어떻게 보이는지는 아무도 확인하지 않았다.**

할 일 — 순서대로:

1. 서버와 dev 서버를 띄우고 1440×900, 1366×768에서 **마을 관찰**을 열어라. 확인할 것:
   - 세 열이 실제로 1:1:1로 보이는가. 3열이 너무 좁아 읽기 어렵지 않은가.
   - 1열의 지도와 '지금 일어난 일' 비율(1.6 : 1)이 적절한가. 지도가 다시 눌리지 않았는가.
   - **가로 넘침 0**: `document.documentElement.scrollWidth === innerWidth`.
   - 1279px 미만(2열), 899px 미만(1열) 전환이 깨지지 않는가.
2. **과밀하면 직접 줄여라.** 15번 9장의 지시다. 3열이 좁으면 섹션을 접거나 우선순위를 낮춰라.
   비율 자체를 바꿔야 한다고 판단되면 사용자에게 먼저 확인해라 — 1:1:1은 사용자가 정한 것이다.
3. `docs/research/screenshots/` 를 만들고 **A~D 네 장**을 파일로 저장해라.
   - A 실험 준비 · B 관찰(그룹 팝오버 열린 지도 + 3열) · C 결과 비교 · D needs_decision 또는 오류.
   - 팁: 직전 세션에서 viewport emulation이 navigate마다 초기화됐다. **navigate 먼저, resize
     나중, 그다음 screenshot** 순서가 통했다. 잘리면 `resize_window({preset:'desktop'})`로
     리셋하고 다시.
4. 15번 9장의 검증 시나리오를 손으로 밟아라. 특히 아직 안 해 본 것:
   - 팝오버 hover 이동 / Escape / 지도 네 모서리 잘림 / '더 알아보기'가 3열을 바꾸는지
   - 차량 동승·귀가 구간이 빈 차로 보이지 않는지
   - 주민 리뷰 근거 클릭이 정확한 버전·시점으로 가며 새 모델 호출을 만들지 않는지
   - 서버 재시작 후 session/버전/cursor 복원

### B. needs_decision과 오류 상태를 화면에서 보기

`needs_decision`은 코드와 서버 검사로는 확인했지만 **화면을 못 봤다.** 도달 설정은 확인됐다:
두 deck · `maxGenerations=2` · `maxCandidatesPerGeneration=3` · `pareto_then_stop`.

할 일: 그 설정으로 실험을 실제로 돌려 결과 비교를 열고, 대안 두 개가 이익/비용/근거와 함께
나란히 보이는지, 이유를 적어야만 '이 방향으로 계속'이 눌리는지 확인해라. 그리고
- 서버를 내린 채 '실험 시작' → **create 실패** 화면
- start만 실패하는 경우 → **start 실패** 화면과 '이 실험 실행 다시 시도'가 **새 세션을 만들지
  않는지** (세션 수를 API로 세어 확인)

### C. 부담 지표를 나눌지 결정 (연구 계약 질문)

`residentBurden.addedTaskMinutes`는 부탁을 들어준 이웃의 시간과, 도움을 받으려고 본인이 움직인
시간을 **같은 필드에 넣는다** (`world.divert`의 `task_ms`). 화면 문구는 이미 정직하게 고쳤고
지표는 건드리지 않았다 — 자세한 내용은 `DEVELOPMENT.md`의 해당 절.

할 일: 나누는 것이 연구에 필요한지 사용자와 정하고, 필요하면 `world.divert` 호출부에서
"부탁 수행"과 "본인 수혜 이동"을 구분해 별도 필드로 세라. **저장된 시도의 값과 비교 가능성에
영향을 주므로**, 최소 변경 범위와 기존 기록을 어떻게 다룰지 먼저 보고해라.

### D. 사용자 사용성 평가

지금까지는 전부 **개발자 내부 확인**이다. 15번 9장의 간단한 사용자 과제 — 설명 없이
"첫 실험 시작", "P1에게 생긴 일 보기", "v0와 v1의 차이 찾기", "현장에서 확인할 질문 정하기" —
를 실제 사람이 수행하는 것은 아직 아무도 관찰하지 않았다.

**사용자를 테스트하지 않았으면 사용자 검증 완료라고 쓰지 마라.**

### E. 선택 사항 — 지도 좌우 여백

은점마을은 남북 1.15 km · 동서 381 m, viewBox 비율 504:1223이다. 1:1:1로 열이 좁아져 여백이
줄었지만 여전히 남는다. **가로로 늘리는 것은 15번 5장이 금지한다.** 더 줄이고 싶으면 지도
패널 폭이나 열 비율 문제이므로 사용자와 상의해라.

## 6. 금지 (15번과 동일, 계속 유효)

엔진 전면 재작성. 원자료·사용자 수정·기존 session 삭제. 관측 불가능한 정보 유출.
가짜 만족도·대화·응급출동. 원래 없던 LLM 능력 표시. 거대한 카드·9px 설명·늘어선 버튼으로

새 UI 프레임워크나 지도 라이브러리 추가. (테스트 러너 vitest·jsdom·testing-library는 이미
devDependency로 들어와 있다 — 런타임 번들에는 들어가지 않는다.)
