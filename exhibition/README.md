# 전시 데모 — 은점마을 사흘 · 27경로

졸업전시(`docs/research/PRESENTATION_2026-09-16_exhibition.pdf`)의 벽면 화면을 미리 보는
**임시 도구**다. 전시장 구성은 벽면 가로 프로젝터 + 앞의 태블릿이고, 이 데모는 그
See → Choice → Apply 루프를 노트북 한 화면에서 돌려 본다.

이 폴더는 저장소의 본 실행 경로(`server/` · `src/`)와 분리되어 있다. medial 본체를 건드리지
않고, 읽기만 한다 — `local-data/normalized/` 의 지도·도로망·일과와 `server/.env` 의 키.

대화록 생성 방식은 다른 저장소(mas-parity)의 **조건 A(전지·일괄)** 를 옮겨 온 것이다.
그 저장소에 기대지 않도록 파서(`lib/parse.mjs`)와 동시성 풀(`lib/util.mjs`)은 이 폴더로
함께 옮겨 두었다.

## 무엇을 만드는가

사흘. 날마다 연구자가 MEDial의 운영 규칙 하나를 고른다. 갈림길 3 × 3 × 3 = **27경로**.

```
1일차   첫 배포 설정 3안 중 하나          → 3 노드
2일차   1일차를 보고 규칙 하나를 고침 3안  → 9 노드
3일차   2일차를 보고 규칙 하나를 고침 3안  → 27 노드
                                            합 39 노드 · 대화록 210건
```

## 어디까지가 규칙이고 어디부터가 모델인가

| | 정하는 것 | 정하는 곳 |
|---|---|---|
| 규칙 | 그 시각 누가 어디 있는지, 부탁을 받을 수 있는지, 언제 출발해 언제 닿는지, 수락·거절·지연, Task 구성, 개선안 후보 | `village.mjs` `plan.mjs` `policy.mjs` |
| 모델 | 그 장면에서 오간 **말**과 하루 끝 한마디 | `prompts.mjs` + gemini-3.8-flash |

medial 설계 원칙 그대로다 — 이동·일과는 LLM이 만들지 않고, 수락/거절은 관측 가능한 제약으로
먼저 판정하고 모델은 표현과 태도만 맡는다.

조건 A(전지·일괄)는 이렇게 돈다. 전지 시스템 프롬프트(상황 + 등장인물 전원 + 서식 규칙)
하나로 한 장면의 대화록 전체를 한 번의 호출로 받고, 발화 수가 안 맞으면 최대 3회 다시 뽑는다.

## 운영 규칙 9개

`server/app/simulation/iteration/semantic_rules.py` 의 `RuleType` 9개·값 범위·한국어 문장을
그대로 옮겼다. 그래서 여기서 고른 개선안은 Change Set과 같은 말이고, 실제 엔진에 그대로 넣을
수 있다. 새 규칙을 발명하지 않는다.

## 사람 자료

`은점마을_페르소나_익명.json` (URP 참여자 정보 폴더). 그 파일이 스스로 "외부 LLM API로 보낼
때는 이 파일을 쓰십시오"라고 적고 있는 **익명본**이다. 실명본은 쓰지 않는다 — 로더가 제목에
'익명'이 없으면 거부한다. 페르소나 본문도, 생성된 대화록도 저장소에 커밋되지 않는다
(`exhibition/out/` 는 gitignore).

## 지도와 일과

정규화 레지스트리 `local-data/normalized/village.v1.json` 을 읽는다. 지도 래스터
(1230 × 490, 1 px = 0.981 m, 북쪽이 오른쪽), 268노드 도로망, 장소 좌표, 12인의 일과
(`plan.baseline`), 이동 속도(걷기 70 · 차 300 m/분)가 전부 거기서 온다. 이동 시간은 다익스트라로
실제 도로를 따라 계산한다 — 검증: P12 자택 → P9 펜션 552 m (인터뷰 기록과 일치), 펜션을 들렀다
가면 원래 동선보다 1,055 m를 더 돈다.

레지스트리가 없으면 `cd scripts && python -m import_village` 를 먼저 돌린다.
다른 곳에 두었으면 `EUNJEOM_REGISTRY` 로 지정한다.

## 실행

```bash
# 키: server/.env 의 GOOGLE_API_KEY (저장소 규칙: 키는 server/.env 에만 둔다)
node exhibition/generate.mjs --plan          # 몇 건인지만
node exhibition/generate.mjs                 # 전부 (끊겨도 다시 치면 이어받는다)
node exhibition/generate.mjs --only 0        # 첫 갈래만
node exhibition/generate.mjs --day 1 --limit 1   # 한 건만 (품질 확인용)
node exhibition/generate.mjs --reviews-only  # 대화록은 두고 하루 끝 평가만 다시
node exhibition/build-html.mjs               # → out/eunjeom-exhibition.html
node exhibition/_read.mjs 0-1-2              # 한 경로를 터미널에서 읽기
```

환경변수: `EUNJEOM_PERSONAS`(익명본 경로), `EUNJEOM_REGISTRY`(레지스트리 경로),
`EUNJEOM_MODEL`(기본 gemini-3.8-flash), `EUNJEOM_CONCURRENCY`(기본 6), `MEDIAL_ENV`(키 파일).

점검: `node exhibition/_audit.mjs` — 시각 어긋남·명단 밖 화자·리뷰 귀속·이동 끊김과,
고른 개선안이 다음 날에 실제로 반영되는지를 센다.

## 산출물 (`out/`, 커밋하지 않음)

- `scenes/<key>.json` — (날, 정책) 조합 하나의 대화록 묶음. 같은 조합은 여러 노드가 나눠 쓴다
- `bundle.json` — 트리 + 계획 + 대화록 전부. **두 화면이 같이 읽는 하나의 원본이다**
- `eunjeom-exhibition.html` — 전시 데모 한 파일 (지도·대화록 인라인, `file://` 로 열린다)
  · `node exhibition/build-html.mjs`
- `eunjeom-3days.html` — 보고용 대화록 뷰어. 27경로를 눌러 다니며 대화록·지표·규칙을 읽는다
  · `node exhibition/build-reader.mjs` (지도는 싣지 않는다)
- `spend.jsonl` — 호출 원장 (실제로 쓴 토큰)

둘 다 `bundle.json` 하나에서 나온다. 계획이나 대화록을 고쳤으면 **두 개를 같이 다시 만든다** —
한쪽만 만들면 교수님께 보여 드리는 대화록과 벽 화면이 어긋난다.

## 경계

- 합성 대화다. 실제 주민의 발언·만족도·동의가 아니다.
- 사람 이름은 가명이다. 마을 이름이 알려진 자리에서는 여전히 재식별 위험이 있다.
- 수치는 절대값이 아니라 조건 간 비교로만 읽는다.

## 화면 (`out/eunjeom-exhibition.html`)

왼쪽에 지도, 오른쪽에 한 열이 계속 떠 있다.

**왼쪽 열** — 지도 · 마을 밖 목록 · 타임라인이 한 열에 들어간다.

지도는 원본 래스터 그대로(북쪽이 오른쪽)라 가로로 길다. 그 위에 **집 열두 채**와 사람을
그린다. 사람은 추출된 도로망(350개 간선) 위에서만 움직인다 — 경로는 다익스트라 결과고 지어낸
선이 아니다.

**마커는 마을 본체 시뮬레이터(`src/features/simulation/components/VillageMap.tsx`,
`Marks.tsx`, `positions.ts`)의 규칙을 그대로 옮겼다.** 그 화면과 이 화면이 다른 그림을
그리면 안 되기 때문이다:

- **이동 경로선은 그리지 않는다.** 길은 래스터에 이미 그려져 있고, 그 위를 지나는 마커가
  곧 경로다. 선을 한 겹 더 얹으면 지도를 덮을 뿐이다.
- **한 자리 = 한 마커.** 같은 곳에 선 사람들은 흰 알약 하나 안에 얼굴을 최대 셋까지
  겹쳐 놓고, 넘치면 `+N`. 겹쳐 보이는 다른 마커는 화면 픽셀 기준으로 밀어 내고 진짜
  자리로 점선을 남긴다.
- **지도 위에 이름은 적지 않는다.** 혼자일 때만 `P1`, 이장은 `이장`. 여럿이면 글자가 없다.
  어느 집에 누가 사는지도 적지 않는다.
- **얼굴**은 번호에서 만들어 낸 도식이다 — 사진도, 실제 주민의 모습도 아니다.
- **차는 사람 위에 얹은 표시가 아니라 옆에 놓인 물건이다.** 태워 주는 동안 운전자와
  동승자는 한 마커가 되고, 점 하나가 실제로 잡힌 자리 하나다. 모르는 빈자리는 그리지 않는다.
- 마커 크기는 전부 화면 픽셀이다. 지도를 키워도 얼굴은 같은 크기로 남는다.
- 진행 중인 요청에 걸린 사람은 알약 테두리가 그 요청 색이 되고, 사건 목록·조율 현황이
  같은 색으로 말한다.

**P 아이콘에 올리면** 그 사람의 나이·직업·지금 있는 곳·관계군과 지금 걸린 요청이 뜨고,
여럿이 모인 마커에서는 **거기 있는 사람이 전부** 뜬다.

읍내에 나갔거나 병원으로 이송된 사람은 지도에서 빠지고 **지도 아래 띠**에 이유와 함께 적힌다
— 지도 위에 얹지 않는다. 배를 타고 나간 사람(조업 구역)도 바다 위 점이 아니라 이 목록이다.

**보낸 사람은 그 일이 끝날 때까지 그 자리에 있는다.** 대화록에서 22분을 동생 곁에서
흉부압박을 하는 사람이 지도에서는 이미 집으로 걸어가고 있으면 안 된다. 일찍 닿은 사람은
기준 일과가 그 자리에 올 때까지 기다린다 — 되돌아가지 않는다.

**오른쪽 위 · 오늘 일어난 일** — 시작한 사건이 쌓인다. 진행 중인 사건은 펼쳐진 채로,
**그 장면의 대화록이 한 줄씩 흘러나온다.** 지난 사건은 접히고, 눌러서 다시 펼친다.

**오른쪽 아래 · MEDial 조율 현황** (위아래 패널 높이는 1 대 1이다) — 요청 하나를 관측 → 판단 → 조율 → 결과로 갠다.
결과는 그 요청이 끝나야 나온다. 아래에 적용 중인 운영 규칙 9문장을 접어 둔다.

**재생 속도는 분/초가 아니라 '대사 한 줄에 몇 초'다.** 사건이 도는 동안은 대사가 읽힐 만큼
천천히 흐르고, 아무 일도 없는 시간은 빨리 감는다. 천천히 1.8초 · 보통 1.0초 · 빠르게 0.55초.

**하루는 22:00까지 간다.** 마지막 사건이 끝났다고 시계를 멈추지 않는다. 22:00에 닿으면 아래에
띠가 뜬다 — "N일차가 끝났습니다 · 오늘 요청 n건 · 확인까지 n분 …" 과 [주민 리뷰를 보시겠습니까]
버튼. 누르면 주민 평가 → 개선안 셋 → 다음 날로 이어진다. 자동으로 넘기지 않는다.

날이 끝날 때까지 마을에 돌아오지 못한 사람은 주민 평가에서 갈린다. **의식이 없어 실려 간
사람은 한마디를 남기지 못한 것으로 두고**(비어 있는 것을 만족으로도 불만족으로도 세지 않는다),
구급차에 같이 탄 사람은 한마디를 남기되 지금 마을 밖이라는 것을 함께 적는다.

이름은 `P1 ◯◯◯` 처럼 번호와 가명을 함께 쓴다 — 대사에서 서로를 이름으로 부르기 때문에
번호만 있으면 누가 누구인지 붙지 않는다. 가명은 익명본의 것이고 실제 인물과 무관하다.

`facts` 중 `※` 로 시작하는 줄은 **모델에게만 주는 연기 지시**다. 프롬프트에는 표시를 떼고
보내고, 화면에는 내보내지 않는다.

**고른 규칙이 걸릴 자리가 있었는지는 화면에서 말하지 않는다** (2026-09-23, 연구자 판단).
한때 두 군데에 적었다 — 선택 카드에 "내일은 이 규칙이 걸리는 상황이 없을 수 있습니다",
다음 날 조율 현황에 "어제 고친 규칙은 오늘 걸리는 자리가 없었습니다". 앞의 것은 내일을 미리
알아야 할 수 있는 말이라 틀렸다. 27경로를 전부 계산해 둔 이 데모만 알 수 있는 것이지,
실제로 이 도구를 쓰는 디자이너는 알 수 없다. 뒤의 것은 참말이지만 화면을 규칙 설명으로
만들어서 같이 뺐다. 관람객은 고른 것이 다음 날에 무엇을 했는지를 사건 목록에서 본다.
